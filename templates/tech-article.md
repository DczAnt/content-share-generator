# 技术长文模板（公众号 / 知乎 / CSDN 通用）

## 产出物结构

Markdown 长文，1500-4000 字，可直接粘贴发布（公众号用 md 排版工具二次排版）。

## 文章结构骨架

```markdown
# 标题：公式 = <痛点/反差> + <具体技术对象> + <收益/悬念>
   例：《NPU 双核利用率永远是 0%？一次 RK3576 排查实录》
   例：《我把 56 个 RK 芯片开发的坑，做成了 AI 编程助手的"记忆"》

> 📷 封面图：用 templates/cards/wx-cover.html（900×383 横版），公众号首图/知乎头图通用

## 导语（100 字内）
   - 结论前置：读完能带走什么 + GitHub 地址首次出现（醒目位置）
   - 引用块：**https://github.com/DczAnt/rk3xx-chip-dev**

## 一、现象（读者代入）
   - 真实报错信息/截图描述/异常数据，细节到位（读者一看"我也遇到过"）

## 二、排查过程（技术分享的核心价值区）
   - 错误方向也写（排除法有信息量）：换了什么→为什么没用
   - 逐步逼近根因的推理链

> 📷 决策树图：用 templates/cards/wx-decision-tree.html（1080×720），插在"排查过程"末尾或"根因"开头

## 三、根因（一句话讲透）
   - 技术原理到位但不堆术语；必要时给架构小图（ASCII/mermaid）

## 四、解法（可直接复制的代码/命令）
   - 完整代码块，注释关键行；给"错误写法 vs 正确写法"对比更佳

## 五、验证（数据说话）
   - 优化前后对比表（数字全部来自 fact-base.md）

> 📷 数据表图：用 templates/cards/wx-data-table.html（1080×600），插在"验证"节末尾，表格可视化版

## 六、沉淀（落点到 skill）
   - 这个坑怎么进入技能包的 + 方法论一句话（五步法）

## 相关仓库
   - rk3xx-chip-dev（地址再次出现）
   - ai_video_monitor_rk3576（实践项目）

## 互动结尾
   - 提问引导评论；关注引导（知乎/公众号）

> 📷 文末引导图：用 templates/cards/wx-cta.html（1080×400），含仓库地址+二维码占位，公众号文末置底
```

## 配图位置速查

| 位置 | 模板 | 尺寸 | 用途 |
|------|------|------|------|
| 文章首图 | `cards/wx-cover.html` | 900×383 | 公众号封面/知乎头图 |
| 排查→根因之间 | `cards/wx-decision-tree.html` | 1080×720 | 决策树可视化 |
| 验证节末尾 | `cards/wx-data-table.html` | 1080×600 | 数据对比表可视化 |
| 文末置底 | `cards/wx-cta.html` | 1080×400 | 仓库地址+二维码引导 |

> 配图与正文不重复：图是把正文里最干货的决策树/数据表"拎出来"做可视化，正文仍保留文字版便于复制。渲染命令见 `cards/README.md` 公众号配图节。

## 平台微调

| 平台 | 调整 |
|------|------|
| 公众号 | 段落更短（手机阅读），小标题加序号，文末引导"在看/转发" |
| 知乎 | 开头呼应问题式导语，逻辑链更严密，可加"先说结论"节 |
| CSDN | 代码块占比可更高，标签齐全（Rockchip/RK3576/RKNN/嵌入式AI），开头给目录 |

## 自检清单

- [ ] 标题含具体技术对象，不空泛
- [ ] 导语 100 字内含收益承诺 + 仓库地址
- [ ] 排查过程含错误方向（排除法）
- [ ] 解法代码可直接复制执行
- [ ] 验证数字与 fact-base.md 一致
- [ ] 仓库地址出现 ≥2 次（导语+结尾）
- [ ] 无敏感信息；事实核对声明已附
